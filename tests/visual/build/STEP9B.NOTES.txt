WHAT
1. Baseline flag V2 (px.reviewBaselineV2). Every device runs the baseline once more. This is safe: it only adds baseline records for
   seen jobs that have no record, a real review always beats a baseline, and nothing is removed.
   The flag is set only when the run made records, or when every seen job already has one. A run with no seen jobs or no scores
   leaves it unset, so it runs again on the next load.
2. Pieces. At most 400 review records per post; the next piece goes once the Writer confirms the last one (a phone's first baseline
   is about 1,800 records).
3. Back on the page (visibilitychange / pageshow / online): pending records go at once, with no 1.5 s debounce, and the pending
   retry is cancelled. With nothing pending, the baseline is checked.
4. System -> REVIEW RECORDS row (phone and desktop):
   "N on this device (B baseline) · P waiting to send · baseline M made HH:MM" or "baseline not run: <reason>",
   then "✓ last send HH:MM · n sent · Writer holds K" or "⊗ last send HH:MM · <error>", plus a SEND NOW button.
   SEND NOW runs the baseline again and sends every record this device holds, at once. A repeat changes nothing on the Writer,
   because it merges by job id.
